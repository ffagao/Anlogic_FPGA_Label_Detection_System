# 本工程综合优化与资源超限处理说明

## 请先明确构建入口

本工程交付位流对应已成功运行的配套脚本流程。本包保留原AL和源码，并不宣称在GUI默认策略下直接点击全流程必定成功。只烧录演示可使用02_下载文件/main_PH1P35MDG324.bit，无需为了查看效果先重新综合。

此前直接在GUI运行曾出现：

`Design's slice number = 21408, exceeds the limit 21216`

这表示当次映射需要21408个Slice，超过器件21216上限192个；不是简单的串口、下载或仿真错误。综合映射、逻辑打包和物理优化策略会改变同一份RTL的资源结果。原AL默认策略没有完整保存成功Tcl流程中的额外设置，因此仅打开AL重新运行不能认为与成功脚本等价。GUI策略修订曾生成过配置文件，但没有完成与成功位流等价的全流程验证，所以没有把它作为本比赛包的默认构建入口。

## 已验证脚本中的优化参数

综合关键设置如下，完整流程以td_project/build_v42.tcl为准：

```tcl
set_param rtl min_ripple_len 32
set_param gate mapper_lut_delay 1800
set_param gate map_mode area_prior
set_param rtl resource_sharing auto
set_param rtl shifter_style shifter_reg
```

min_ripple_len控制专用进位链的采用门槛；area_prior使映射优先考虑面积；resource_sharing允许共享资源；其余参数影响映射与移位结构。它们是一组经原工程成功流程使用的配置，不是对所有设计都有效的通用最优值。

物理实现还使用特定位置参考、布局密度、拥塞与时序优化、high布线力度、post_route_opt ultra以及额外时序裕量目标。只把route effort改成high，并不能解决综合阶段本身Slice超限。

## 推荐完整操作

1. 将完整01_FPGA工程复制到纯英文路径，例如E:/contest_fpga，不要只复制AL。
2. 使用TD 6.2.168116，核对器件PH1P35MDG324、速度-3、顶层design_top_wrapper。
3. 在该目录打开PowerShell。若TD安装在默认位置，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\rebuild_v42.ps1
```

安装位置不同则运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\rebuild_v42.ps1 -TDHome 'E:\Anlogic\TD_6.2.1_Engineer_6.2.168.116'
```

将TDHome改为实际安装目录。脚本会调用prepare_project.ps1更新AL根路径，选择可用临时盘符，运行成功流程并检查产物更新时间。已保留reports、release目录，分别接收日志与新位流。内部v42文件名是历史命名。

4. 阅读reports/v42_build_console.log。应看到V42 BUILD SUCCESS；脚本正常退出，且td_project/v42_dynamic_label.bit为本次新生成的文件。
5. 同时核对本次area和timing报告，不只凭bit文件存在判断成功。原报告仍可能被保留，需看生成日期和日志。

## 如何判读资源报告

原成功流程Gate阶段Slice打包估算20964，最终物理实现Slice20099；这两个数属于不同阶段，不能直接相减声称某个优化独立节省了865个Slice。最终资源为LUT6 19776、Slice20099、ERAM92、DSP33。最终SWNS +0.318ns、HWNS +0.045ns。详细数据见本工程验证与资源报告。

构建过程必须同时满足器件容量、布局布线可实现性与时序要求。资源不超限不等于布线成功，布线成功也不等于所有受约束路径时序通过。

## 如果必须通过GUI按钮构建

Run Properties / Flow Options中可查看和设置策略，必须从Read Design重新运行，而非复用旧默认综合数据库。但GUI保存策略、通用参数与阶段调用可能不等同于Tcl脚本，不应只输入几个参数后保证通过。完整固化GUI策略并重新验证属于后续工作；本包的推荐复现方法仍是配套脚本。

不要盲目删除业务逻辑、改小器件型号或放宽时钟周期来掩盖错误，也不要把旧bit当作本次生成结果。

## 报错时保留什么

保留第一条ERROR及前后约30行、TD版本、实际运行命令、工程路径、当次Gate/Physical资源报告。Slice超限重点检查综合策略；PHY拥塞错误重点检查布局布线和资源密度；找不到文件重点检查解压完整性和路径；许可证问题单独处理。界面Physical failed弹窗本身不能定位原因。
